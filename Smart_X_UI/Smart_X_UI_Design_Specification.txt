SMART X - UI DESIGN SPECIFICATION
===================================

Project:
Smart X

Purpose:
This file records the important visual and UI design decisions for the Smart X
Avalonia desktop application so that future screens can follow the same design.

--------------------------------------------------
1. APPLICATION STYLE
--------------------------------------------------

UI framework:
- Avalonia UI
- C#

Overall visual style:
- Dark blue engineering / control-system interface
- Simple and practical rather than highly polished or futuristic
- Designed to look like a real student-built desktop application
- Clear hierarchy and readable controls
- Avoid excessive cards, badges, gradients, animations, or decorative elements

Application window:
- Title: Smart X
- Main window size: 650 x 850
- Dark background
- Comfortable margins around the content

--------------------------------------------------
9. TYPOGRAPHY
--------------------------------------------------

General typography:
- Use the default Avalonia/system font unless a project-wide font is
  deliberately introduced.
- Prefer SemiBold for headings.
- Use normal weight for descriptions.
- Avoid excessive bold text.

Recommended sizes:
- Main title: 30
- Section heading: 17
- Module title: 18
- Description: 13
- Status text: 12
- Footer: 11

--------------------------------------------------
11. DESIGN PRINCIPLES
--------------------------------------------------

1. Keep the interface simple.
2. Use dark navy as the dominant colour.
3. Use blue for interface structure and active elements.
4. Use green primarily for availability and successful status.
5. Disabled functionality should be clearly visible but subdued.
6. Avoid unnecessary visual effects.
7. Keep text readable at normal desktop viewing distances.
8. Keep controls large enough to click comfortably.
9. Maintain consistent spacing and corner radii.
10. New screens should follow the same colour palette and hierarchy.
11. The UI should support the architecture rather than hide it.
12. The three architectural pillars should remain consistent throughout
    the application.


--------------------------------------------------
12. ARCHITECTURE / UI RELATIONSHIP
--------------------------------------------------

The Avalonia application is the frontend.

The application communicates with a separate self-hosted ASP.NET Core
Web API.

Frontend:
- Smart_X_UI
- Avalonia UI
- C#

Backend:
- Smart_X.Api
- ASP.NET Core Web API
- C#

The frontend should communicate with the API over HTTP rather than
directly referencing backend processing classes.

Business logic, processing, database operations, and API functionality
should remain separated from the user interface.


--------------------------------------------------
13. CURRENT STARTUP INTERFACE
--------------------------------------------------

The startup screen provides access to three architectural pillars:

1. Sensor Data Ingestion and Telemetry
   - Enabled
   - Implemented in Part 1

2. Real-Time Command Stream and History
   - Disabled
   - Planned for Part 2

3. Network Topology and Mesh Routing
   - Disabled
   - Planned for the final PoE

Only the functionality required for the current assignment stage should
be enabled.
